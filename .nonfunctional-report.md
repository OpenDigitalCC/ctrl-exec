# Non-functional report - ctrl-exec

Date: 2026-06-19
Scope: full project at HEAD `ea16578` (release line 0.11.1 shipped, 0.11.2 staged)
Auditor: Claude

## Method

The audit ran nine specialist sub-audits in parallel. Five cover the mandatory
non-functional dimensions; the security dimension was split into five adversarial
planes, each told to verify every claim against the code and to separate
*documented, intentional* limitations from *genuine undocumented* weaknesses
"outside the set boundaries":

- C root executor (`src/ctrl-exec-exec.c`) - memory safety, privilege drop, protocol parser.
- Perl front-end exec path - command injection, allowlist bypass, environment.
- PKI / pairing / rotation - cert validation, identity-from-serial, the trust chain.
- HTTP API / auth hook / authz - default-deny, the hook contract, input validation.
- Filesystem / IPC / config / secrets - socket perms, key modes, systemd hardening.

Tooling actually run: `prove` (836 tests pass), `Devel::Cover`, `gcov`, `cppcheck
2.17.1`, `clang --analyze`, `clang-tidy 19`, `perlcritic 1.156`, `shellcheck 0.10`.
The top security findings below were re-verified by direct code read before
inclusion. `gitleaks`/`trufflehog` are **not installed on the host** - the
automated secret sweep could not be run (manual inspection found no committed
secrets).

The headline: the architecture is sound and the documented trust boundaries hold.
No unprivileged-attacker path to root or to allowlist bypass was found. The real
findings cluster in three places the design does not currently cover -
**environment inheritance into executed scripts**, the **CSR-signing path**, and
**resource/DoS bounds on the API and the async store**.

## 1. Test coverage

**Method.** `Devel::Cover` over the Perl suite (836 tests, all passing under
instrumentation); `gcov` on the C executor driving the conformance/roundtrip
scenarios.

**Findings.**

```datatable
columns: Component | Coverage | Note
widths: 6cm | 3cm | X
bold: 1
tone: medium
---
Perl library + in-process | 75.9% stmt / 52.4% branch | Optimistic: two of three binaries are excluded from the denominator.
`lib/Exec/API.pm` | 20.9% | Every HTTP handler at 0; server never started in unit tests.
`bin/ctrl-exec-dispatcher` | 24.1% | Only pure parse/format helpers tested.
`bin/ctrl-exec-agent` (1356 lines) | ~0% in-process | `main()` called with no `unless caller` guard, so no sub is loadable for unit test.
C executor privileged block (exec.c:454-522) | 0% automated | `unshare`, bind-mounts, cap drop, setuid - the security boundary - is "compile-verified" + on-host manual only.
```

- The single largest file and the single most security-critical code block both
  have **no automated coverage of their core paths**. The C privilege-drop is
  exercised for *decision* parity (`exec-conformance.t`) but never for *effect*
  (no test asserts the bounding set actually shrank or the uid actually changed).
- `t/header-limit.t` is `plan skip_all` - it asserts nothing. `t/tls.t` asserts
  only on the static cipher/version hash; it opens no connection and never proves
  an untrusted or expired client cert is rejected. Both read as coverage of
  things that are not, in fact, covered.

**Recommendations (ranked).**

1. Add an `unless caller` guard to `bin/ctrl-exec-agent` (and ideally extract an
   `Exec::Agent::HTTP` module). Highest leverage: it unblocks unit tests for
   `handle_run`, `handle_connection`, and the header-limit guard in one move.
2. Add a root-gated CI lane (or privileged container) that runs `apply_profile`
   for real and asserts post-conditions (effective uid switched, bounding set
   reduced, control dirs read-only). Until it exists, label the executor boundary
   "manually verified only" in the release checklist.
3. Add a negative-mTLS unit test (wrong-CA / expired cert is refused) and an
   in-process `API.pm` handler test; un-skip `header-limit.t`.
4. Target for 0.12: 85% statement / 70% branch on the library; the gap is almost
   all branch/condition coverage in `Engine`, `Rotation`, `Pairing`, `API`.

## 2. Code quality

**Method.** `perlcritic --severity 3`, `cppcheck --enable=all`, `clang-tidy`,
`shellcheck -S style`; manual complexity and duplication review.

**Findings.**

- **C is clean.** `cppcheck` found only 9 "could be const" style notes; the
  `clang-tidy` warnings are all Annex K `_s`-function false positives (glibc does
  not implement them) and are discarded. No memory/format/bounds findings.
- **Perl `perlcritic`** is 480 violations but ~95% house-style noise (missing
  trailing `return`, no-`/x` regex, `record` naming). The signal items:
  `return undef` in list-returning subs (24 sites - returns a 1-element list, a
  latent caller foot-gun) and `$ENV`/`$SIG` not `local`ised in `Auth.pm` /
  `API.pm` / `Pairing.pm`.
- **Duplication that has already diverged** (the dangerous kind):

```datatable
columns: Duplication | Locations | Why it bites
widths: 5cm | 5cm | X
bold: 1
tone: medium
---
Output formatters | `Exec::Output` vs `bin/ctrl-exec-dispatcher` inline | The dispatcher reimplemented all four formatters and they have drifted (it added `reported_hostname`/`req:`); the library copy is kept alive only by `t/output.t`. The tested copy is the one nobody runs.
HTTP response writer | agent `_send_raw`, `API.pm` `_send_json`, `Pairing.pm` `_send_raw` | Status-phrase tables drifted: a real 500 prints "Error" on the agent path; any new code must be added in 3-4 places.
```

- **Dead code:** `AgentPairing::request_pairing` (86 lines, an orphan twin of the
  live `submit_pairing_request`, in a security-sensitive module - a maintainer
  will eventually patch the wrong one) and `Log::close_log`.
- **Complexity hotspots:** `mode_serve` (agent:73, ~221 lines), `handle_run`
  (agent:776, ~211), `run_pairing_mode` (Pairing.pm:80, ~196, depth 6),
  `_validate_config` (Config.pm:69, depth 6 - must stay in lockstep with the C
  parser), `apply_profile` (exec.c:439 - every line privilege-bearing).
- **No undated TODO/FIXME in source** - clean.

**Recommendations (ranked by reach x risk).** (1) Resolve the output-formatter
fork - route the dispatcher through `Exec::Output` or delete the module + its
test; the divergent copy is in production. (2) One shared HTTP-response helper.
(3) Delete `request_pairing`/`close_log`. (4) Decompose `mode_serve`/`handle_run`
- 430 combined lines where every future agent change lands. (5) `return` not
`return undef` in list-returning subs. Suppress the house-style noise via a
`.perlcriticrc`, not 230 edits.

## 3. Performance

**Method.** Structural analysis (no paired-mTLS workload is trivially runnable in
the sandbox). All three servers are fork-per-connection.

**Findings - unbounded-growth structures are the real risk, not CPU.**

```datatable
columns: Risk | Evidence | Bites at
widths: 5.5cm | 5cm | X
bold: 1
tone: strong
---
Agent async run store never purged | `AsyncRunner::purge_expired` (AsyncRunner.pm:160) is dead - called from nowhere | Day one of async use; inode exhaustion by ~10⁴-10⁵ runs.
Unbounded dispatch fan-out | `Engine` forks one TLS client per host up to `max_hosts=500`, no worker pool | ~500 concurrent forks + ~1500 fds hits the 1024 fd soft limit before the host cap.
`Registry::list_agents` O(fleet) JSON sweep | opendir + decode_json every `*.json` per call; called on every list/discovery/rotation pass | A wall at ~10⁴ agents.
Lock files never deleted | `Exec::Lock` flock-releases but never unlinks | Slow inode growth; `list_held` cost grows with it.
Agent reaps one zombie per accept | agent:291 single `waitpid`, vs API/executor reap-all loops | Zombie pile-up under bursty-then-idle traffic.
```

- **Good:** agent config is cached and SIGHUP-reloaded (not per-request); the
  rate limiter is bounded and self-evicting (cap 1000); the executor socket
  round-trip is a compact length-prefixed frame, negligible latency.
- TLS handshake happens in the agent's accept loop *before* fork, so it
  serialises - the real connection-acceptance ceiling, but only matters at high
  connection rates.

**Recommendations (ranked).** (1) Wire `purge_expired` into a systemd timer or an
opportunistic call on `/run`/`/result` - this is a live leak. (2) Windowed
worker pool (32-64 in flight) in `Engine` - highest payoff, near-zero latency
cost since dispatch is RTT-bound. (3) Cache/index `list_agents`. (4) Unlink lock
files on release; timer-driven dispatcher run-store purge (today it purges only
lazily on a status poll). (5) Make the agent reap-all like the other two loops.

## 4. Security

**Method.** Five adversarial planes (see Method). `perlcritic --theme=security`
was clean on the core modules; the findings below are manual, and the high-impact
ones were re-verified by direct read.

The documented boundaries hold: no shell in the exec path (`execv` / list-form
`exec {}`), the executor re-derives path+profile from its own root-owned config
and never trusts the wire, peer-cred-gated `0600` socket in a root-owned runtime
dir, default-deny API applied to *every* route, TLS 1.2/1.3-only with a
centralised hardened cipher policy, CSPRNG for reqids/nonces, no committed
secrets, atomic traversal-proof state writes. These are genuinely well built.

The weaknesses are where the design has *not yet* drawn a boundary:

::: widebox
The three security themes worth acting on: (1) **environment is never sanitised**,
so the documented "no shell" guarantee does not extend to the scripts the agent
runs; (2) the **CSR-signing path validates nothing** about the subject/key, and
the renewal feature that would exercise it is advertised but unimplemented;
(3) the **API and the async store have no resource bounds**, giving a
pre-authentication DoS and an unbounded disk leak.
:::

**Ranked findings.**

```datatable
columns: # | Severity | Finding | Boundary
widths: 0.8cm | 2.2cm | X | 2.6cm
bold: 1 3
tone: medium
---
S1 | High | API server has no body/header size cap (API.pm:154-167): attacker-supplied `Content-Length` honoured, no header-count limit, unbounded `fork()` - pre-auth memory/fork DoS. The agent caps both (32 headers/1 MiB); the API does not. | Outside
S2 | High | `sign_csr` (CA.pm:119-173) signs any CSR with no subject/key-size/algorithm check; agent cert CN is never verified. A holder of one signed cert can mint a cert naming another identity. | Outside (doc says "CN not checked" but the gap is wider)
S3 | High | Advertised auto-renewal is non-functional: agent router (agent:657-669) has no `/renew` handler, yet Engine.pm:922/944 POSTs `/renew`+`/renew-complete`. Certs silently never renew; when fixed, the handler sits atop S2's unvalidated signing. | Outside (doc-vs-code)
S4 | Medium | Environment never sanitised in *either* mode: Perl `Runner.pm` and C `execv` both pass the full parent `%ENV` (PATH, LD_*, BASH_ENV, IFS, PERL5LIB) to the script. "No shell" does not protect shell/perl/python scripts in the allowlist. | Outside
S5 | Medium | `run_as` numeric parse (exec.c:486-494) has no overflow guard; a value whose low 32 bits are 0 truncates to uid 0 (root). Needs root-config write to trigger, so footgun more than escalation, but a silent privilege non-drop. | Outside
S6 | Medium | `/capabilities` fails open when the trusted-dispatcher map is empty (agent:1040-1059): full allowlist + paths returned to any CA-signed peer. Every other endpoint hard-denies on an empty map. | Inside (warned) but wrong default
S7 | Medium | Auth hook has no execution timeout (`Auth.pm:260` blocking `waitpid`): a hung hook wedges the forked request forever. Hook error-handling is otherwise correctly fail-closed. | Outside
S8 | Medium | CA/dispatcher key written by `openssl genrsa` at umask-default (0644) then `chmod 0600`; a `ctrl-exec`-group member can win the race on an already-open fd. The crown-jewel CA key has a world/group-readable window. | Outside
S9 | Medium | `initgroups()` return ignored (exec.c:498); a failure leaves the wrong supplementary group set rather than aborting. | Outside
S10 | Medium | `$config` not reloaded on SIGHUP (agent:152-169) - only allowlist/trust/schema are. An operator who edits agent.conf to *tighten* (add script_dirs, enable auth_hook, switch to executor mode) and HUPs believes it took effect; it didn't. Fail-open surprise. | Outside
S11 | Medium | `/status/{reqid}` returns any caller's run output, and the API passes no reqid/submitter into the auth context, so a hook *cannot* owner-gate it even though the docs tell operators to. | Inside (documented) but unfixable-by-hook
S12 | Low-Med | Pairing confirmation code is `sha256(csr)` only (Pairing.pm:906) - non-binding to channel/dispatcher; a relay shows the same code. It is a transcription check, not anti-MITM; the doc overstates it. | Inside (doc overstates)
S13 | Low-Med | Sequential, predictable CA serials (CA.pm:51), and the serial *is* the identity. Not a break alone, but removes all defence-in-depth around identity. | Inside (intent) but predictability unintended
S14 | Low-Med | API runs `User=root` to read certs/write runtime dirs - both doable as a `ctrl-exec`-group user. A parser bug in the network-facing JSON path is then remote-root if `api_bind` is ever non-loopback. | Outside (defence-in-depth)
S15 | Low | `args` elements not type-checked (agent:798): refs/undef stringify to `ARRAY(0x..)` argv tokens (address leak), not a shell escape but an integrity hole. Lock files open without `O_NOFOLLOW`. Source-IP is meaningless behind a proxy but presented as a hook policy input. | Mixed
```

**What is solid (verified).** The protocol frame parser (`take_field`/`read_all`)
is overflow-safe and bounds every length field; `argv` bounding has no off-by-one;
there is genuinely no implicit `CAP_DAC_OVERRIDE` (bounding set reduced to exactly
the profile caps, `cap_set_proc` from empty); peer-cred check is fail-closed and a
different-uid process cannot open the `0600` socket; the allowlist cannot be
escaped by the request (path from the allowlist value, `abs_path` symlink/`..`
collapse, re-validated at exec); the auth gate is default-deny on every route with
no CLI-allow bleed; the token is never logged, stored, or echoed; no SSRF (hosts
validated against the registry); serial normalisation is careful and well-tested;
CA/dispatcher keys are `0600` and signing is flock-serialised.

**Recommendations - fix this release vs harden later.**

*This release (0.11.2 / 0.12):* S1 (mirror the agent's `Content-Length`/header
caps into `API.pm` - small, concrete), S4 (scrub `%ENV` to a minimal allowlist
before `exec` in both `Runner.pm` and the C `execve`), S3+S2 (decide: implement
`/renew` *with* CN-pinning and CSR validation, or remove the dead renewal path
and the "auto-renew" claim until built - do not ship the handler on top of an
unvalidated `sign_csr`), S5 (reject `(uid_t)v != v` and bound at config load),
S6 (fail closed on an empty trusted map), S7 (`alarm()` the hook, fail closed).

*Hardening later:* S8 (`umask(077)` around `openssl genrsa`), S9, S10 (reload
`$config` on HUP or document restart-required), S11 (thread reqid/submitter into
the `/status` auth context), S12-S14, S15.

## 5. Documentation

**Method.** README walk-through, doc-vs-code spot-checks on security claims,
OpenAPI/SBOM/changelog drift checks.

**Findings.**

- **Strong overall.** README follows what/install/quickstart/where-next; all
  cross-references resolve (including the newly-added `TROUBLESHOOTING.md`); ports
  and subcommands are consistent; CHANGELOG is current to HEAD and
  commit-ref-anchored; human and robot docs are not interleaved. Every
  security-sensitive *human-doc* claim verified true against code (no-shell,
  default-deny API vs default-allow CLI, profiles enforced only by the executor,
  `writable` parsed-but-not-enforced, libc6 floor, exit-78 no-restart-loop).
- **Stale stamps / drift:**

```datatable
columns: Item | Location | State
widths: 5cm | 5cm | X
bold: 1
tone: light
---
SBOM version | `sbom.json` | Stamped 0.11.1 vs HEAD 0.11.2. Component set is identical (no dependency drift); self-corrects at release via make-release. Re-stamp or note.
OpenAPI `info.version` | `openapi.json:6` | `0.2.8` - four minors stale. Live route overwrites it at runtime, but the repo + `GET /openapi.json` show the placeholder.
OpenAPI spec vs code | `openapi.json` | Lags: `/`, `/openapi.json`, `/openapi-live.json` undocumented; `RunResponse.reqid`, `HostCapabilities.tags`/`reported_hostname`, 404s missing. `docs/API.md` (the human ref) is complete.
```

- **Two wrong in-code comments** (the kind that mislead a future maintainer):
  `exec.c:13-18` says the socket server and privileged exec path "land in phase
  2b" - they are all present in this file now; `Config.pm:90-91` says the
  executor "applies these ... `writable` ..." before exec, but `writable` is
  parsed and **never enforced** - this contradicts the code *and* the (correct)
  `TROUBLESHOOTING.md`.

**Recommendations (ranked by reader cost).** (1) Fix the two misleading code
comments - they sit in the two most security-critical files. (2) Re-stamp
`openapi.json` `info.version` and reconcile the spec with the code (or state that
`API.md` is the authoritative reference and the static spec is a seed). (3)
Re-stamp the SBOM at 0.11.2 cut. (4) The `website/changelog.md` stub is three
months stale - either transcribe on release or drop the placeholder.


No finding blocks the 0.11.2 doc release. For a 0.12 *functional* release the
fix-this-release security set (S1-S7) is the priority, led by environment
scrubbing and the API size cap as the two most concrete, and the
renewal/`sign_csr` decision as the one with the widest blast radius.
